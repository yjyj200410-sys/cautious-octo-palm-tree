# doto 安卓非播放页横屏适配实施计划

目标是让横屏多出的宽度用于浏览，让有限的高度留给内容。用户应能在搜索、看歌单或勾选歌曲的中途旋转手机，接着完成刚才的操作。交付范围为 Android 原生 Java 界面。已完成左右分栏的全屏播放页作为衔接与回归对象。

## 先处理页面外壳

代码入口位于 `mobile/app/src/main/java/com/volo/mobile/`。先读 `MusicActivity.updatePageViewport`、`switchMainTab`、`FloatingNavigation`、`CompactPlayerView`、`PlayerMorph` 和 `mobile/design/doto-design-language.md`。目前正文顶部按 80dp 预留可滚走的空间，底部净空依据悬浮导航的实际位置计算。搜索页对摄像头的特殊处理主要读取顶部 inset。转成横屏后，摄像头和系统导航可能在左侧或右侧，底部胶囊与播放器过渡也共用几何位置。

1. 按当前窗口扣除系统栏和挖孔后的可用宽高决定排版。建议初值为可用宽 ≥ 640dp、横向且正文列能容纳 320dp 时允许分栏。分屏或大字号导致放不下时退回单列。键盘只改变可见高度，输入中避免来回切换模板。
2. 横屏保留 20dp 内容基线、底部胶囊 12dp 悬浮距离和上下边缘渐隐。可点击内容从安全边界向内对齐，装饰背景可铺满。以 16dp 为栏间距初值。顶部首项避让用实际按钮下缘计算，末项仍能滚到胶囊上方，避免重新出现固定黑带。控件触控区至少 48dp。
3. 主 Activity 已声明自行处理方向和窗口尺寸变化。用窗口布局变化更新现有页面；以可用宽度档位参与渲染缓存判断，特别是 `personalRenderKey`。数据与布局分开更新。记录当前路由、列表首个可见条目的稳定标识与偏移，重排后恢复。不要靠重新打开首页或重新发网络请求触发重排。
4. 核对悬浮导航、迷你播放器、选歌操作条与播放器展开起点在同一窗口坐标系。先验证两端不会互相覆盖，再开始逐页调整。

## 逐页布局与验收

| 页面及代码入口 | 横屏怎么排 | 现场验收 |
| --- | --- | --- |
| 发现首页：`renderDiscovery`、`renderFeaturedGrid`、`renderPlaylistShelf`、`renderCuratedSongPages` | 顶部两个主要入口并排；下方歌单封面按可用宽度增加可见项，保持方形。推荐歌曲按原顺序铺排，轮播与翻页继续使用原手势。页面共用一条纵向滚动轴。 | 首屏能看到入口和实际推荐内容；横滑歌单不会误切主标签；旋转后仍位于原推荐区块，卡片点击对应原歌曲。 |
| 搜索：`showSearch`、`showSearchState`、`searchSongs`、`showSongs` | 搜索框限宽居中，保持纯色并随正文滚动。搜索结果保留单列阅读顺序，宽屏限制正文行宽。键盘展开时压缩可见视口，确保输入、清除和首条结果可操作。 | 输入中文到一半旋转，检查焦点、组合输入、查询词和结果；搜索中旋转一次再改词，旧结果不能覆盖新结果；返回回到原入口。 |
| 我的：`renderPersonal`、`showAccount` | 左栏约 30% 放账号和最近播放、本地音乐、已下载入口；右栏放分类及收藏内容。两栏不足时恢复纵排。访客与已登录共用骨架。 | 从“专辑”旋转仍在专辑分类；长昵称、未登录、空收藏和多歌单都能浏览；慢请求回来后维持横屏排版。 |
| 日推、歌单、专辑、最近播放、本地音乐：`openSongs`、`openPlaylist`、`openDailySongs`、`showLocalMusic`、`SongListPanel` | 有封面与简介的详情，左栏放摘要和播放操作，右栏给歌曲；最近播放、本地音乐等轻量列表用紧凑标题加单列。复用现有行、过滤、索引和多选逻辑；选择操作条随安全区定位。 | 长标题及译名不盖住更多按钮；筛选后点歌、批量选择和下一首对应正确 ID；横竖屏往返保留勾选和滚动位置；最后一首能完整点到。 |
| 下载与分轨结果：`renderDownloads`、`showStemLibrary` | 短标题和批量操作同排，文件名、状态和进度组成单列；窄时允许操作换行。先检查已有入口与真实数据，再处理空状态。 | 下载中的进度跨旋转连续，点击仍作用于原任务；长文件名、失败和空列表时操作可见。 |
| 设置：`SettingsActivity.buildPage` | 宽屏将播放设置与外观设置分两栏，短屏可纵向滚动。颜色编辑、选择图片等沿用原入口；设置页独立处理四边 inset 和键盘。 | 切换设置后旋转值仍正确；输入颜色时按钮可达，系统选图返回原设置项；退出回原页面。 |
| 队列与临时弹层：`QueueSheet`、`SongListPanel.showSelectionDrawer`、账号/二维码弹窗和 `MusicActivity.popup` | 队列与长菜单限制高度、内部滚动；弹窗按安全宽度限宽。二维码保持正方形，窄高时把说明移到旁边；菜单旋转后重新定位到触发控件。 | 检查队列当前项、拖排、批量操作、弹窗关闭和系统返回；左右两种横屏方向都能点到最后一个操作。 |

## 实施顺序与交接

1. **公共外壳**。先交付可用宽度判定、安全区、滚动净空和悬浮组件定位。用同一台手机保留改动前后的发现页截图，并记录窗口 dp 和 inset。
2. **浏览主链路**。依次完成发现 → 搜索 → 歌单详情 → 播放 → 返回，再做我的及其子页。共享列表布局在 `SongListPanel` 实现一次，各入口仅提供内容与动作。多个执行者协作时，让一人整合 `MusicActivity.java`，避免同时改公共渲染逻辑。
3. **设置与弹层**。检查独立 Activity 重建、弹窗锚点、输入法、系统选图和返回栈。沿用现有 Android View 和设计组件。
4. **回归交付**。在 `mobile` 目录执行 `gradlew.bat :app:assembleDebug :app:lintDebug :app:assembleDebugAndroidTest`。复用 `PlaybackInstrumentation` 中的 `selection-layout`、`queue-sheet`、`appearance-settings`；检查既有用例是否依赖竖屏坐标，另用真机覆盖横屏流程。

## 完成标准

- PKR110 上检查竖屏、左右横屏，以及播放中旋转、暂停时旋转、键盘展开和多选中旋转；再用分屏或模拟器覆盖低于分栏阈值的窄窗口。至少一次使用放大字体检查文字与按钮。
- 走通“发现 → 歌单 → 全屏播放 → 收起 → 原歌单”和“我的 → 搜索或本地列表 → 返回”。核对播放队列、曲目、进度、筛选、滚动锚点和已选项。用暂停曲目验证页面旋转本身不会开始播放。
- 每种布局模板至少提交一张横屏截图；左右挖孔、旋转中保留状态、末项可点和菜单可达要实操验证。记录机型、窗口尺寸、测试命令、通过与未验项目。测试结束恢复设备原有旋转设置。
